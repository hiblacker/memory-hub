# 测试策略

## 目标

测试优先保障四类风险：重复归档、敏感信息泄露、来源工具被阻断、思源状态与数据库状态不一致。

## 测试层级

### 单元测试

- Vue：组件状态、筛选器、规则表单和错误提示，使用 Vitest + Vue Test Utils。
- 领域：状态机、规则匹配、canonical key、指纹、冲突和版本替代。
- 安全：Token/密钥检测、脱敏、URL 白名单和导入文件校验。
- 适配器：思源请求映射、模型结构化结果校验和来源事件映射。

单元测试不连接真实模型、思源或网络。外部响应使用固定 fixture；fixture 禁止包含真实对话和密钥。

### 集成测试

- 使用 Testcontainers 启动 PostgreSQL，验证迁移、唯一约束、事务和 pg-boss 重试。
- 使用本地 HTTP Stub 验证思源 401、超时、重复提交、部分成功和恢复。
- 对 `SourceEvent` 建立版本化契约测试，保证 Claude Code 和浏览器扩展升级不破坏核心服务。

### 端到端测试

- Playwright 覆盖登录、手动录入、候选审核、规则试运行、手动归档和失败重试。
- CI 使用模拟思源服务；真实思源契约测试必须显式启用，不在普通 CI 中运行。

### 部署与恢复测试

- 重启 API、Worker 和 NAS 后任务不丢失。
- 备份恢复到空实例后候选、版本、规则和归档记录一致。
- 思源离线期间产生的归档任务在恢复后按顺序完成。

## 覆盖率门槛

- 全仓库语句和分支覆盖率不低于 80%。
- `packages/core`、`packages/security`、`packages/siyuan` 不低于 90%。
- 覆盖率不能代替状态机、失败路径和幂等场景测试。

## 必测场景

1. 相同 Hook 事件连续提交十次只创建一个处理链。
2. 两条相互冲突的永久事实不能自动归档。
3. 包含 API Key 的文本不会进入模型请求或思源正文。
4. 思源成功写入但响应丢失时，重试不会创建重复块。
5. 规则处于试运行状态时不产生真实交付。
6. 模型返回非法 JSON、超时或拒绝响应时保留来源事件并可重试。
7. 数据保留任务删除原始负载后仍能查看候选来源摘要和哈希。

## CI 门禁

每个 PR 必须通过格式检查、lint、类型检查、单元测试、数据库集成测试和构建。主分支额外执行端到端测试、镜像构建与漏洞扫描。
