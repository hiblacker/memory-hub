# ADR-0004：记忆正文采用 Markdown，并提供双风格预览

- 状态：Accepted
- 日期：2026-08-15

## 决策

MemoryHub 的候选记忆正文以 Markdown 为唯一真相源。

管理端在手动录入页和候选详情页复用同一套 Markdown 编辑/预览组件。默认进入仅预览模式，提供小红书笔记风（默认）与简洁技术风两套排版，两套风格均使用 emoji 增强可读性。

V1 不支持图片 Markdown；是否支持图片见 `docs/TODO.md`，待定。

以下能力从需求中删除，不再排期：

- LLM 自动润色
- 完整 WYSIWYG 富文本
- 小红书图文瀑布流 / 贴纸引擎
- 思源正文回写
- 自定义 CSS 主题市场

## 原因

- 思源归档路径本身以 Markdown API 为主，源文使用 Markdown 可减少格式转换损失。
- 审核场景需要先快速阅读再修改，默认仅预览更符合收件箱工作流。
- “小红书笔记风”提升扫读体验，但工程决策和项目上下文仍需要更克制的“简洁技术风”。
- 两套风格都保留 emoji，可统一分区扫读习惯，避免一种活泼、一种枯燥的割裂体验。
- 自动模型改写、复杂图文引擎和主题市场会显著扩大安全面与维护成本，且不是 MemoryHub 核心闭环。

## 预期后果

- 需要引入受控的 Markdown 编辑器与 HTML sanitizer。
- `body` 校验与列表摘要需按 Markdown 处理。
- 归档渲染应复用同一风格约定，保证管理端预览与思源阅读结构接近。
- 文档、测试和实现不得再把已删除能力当作隐含后续需求。

## 后续工程约定

- 共享组件优先落在 `apps/web` 的可复用模块中。
- 风格与 emoji 开关需可保存，避免每次打开丢失用户选择。
- 完整规范见 `docs/13-memory-markdown-formatting.md`。
