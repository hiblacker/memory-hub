# V1 范围与开发顺序

## V1 必须完成

- 单管理员登录、连接器 API Key 和基础审计。
- 手动录入、标准 REST 事件接收、Claude Code Hook。
- ChatGPT 显式保存扩展和官方导出文件导入。
- 可配置模型 Provider，关闭模型时支持纯人工流程。
- 脱敏、分类、精确去重、近似重复提示和冲突阻断。
- 候选收件箱、来源查看、编辑、批准、拒绝、合并和批量操作。
- 声明式自动归档规则及试运行。
- 思源连接测试、目标配置、手动归档、自动归档、幂等和重试。
- 关键词搜索、来源/类型/状态/项目过滤。
- Docker Compose、备份恢复、健康检查和升级文档。

## V1 不包含

- ChatGPT 页面自动监听、后台抓取和隐藏长期记忆读取（项目明确不提供）。
- 向量数据库、知识图谱和复杂 Agent 自主召回。
- 多用户、OIDC/LDAP、移动端和公网 SaaS。
- 附件 OCR、视频转写和网页全文归档。
- 思源到 MemoryHub 的完整双向同步。
- 自动删除或静默覆盖已归档记忆。

## 开发顺序

1. **工程基线**：monorepo、格式化、lint、单元测试、CI、Compose。
2. **数据库与契约**：Drizzle schema、迁移、SourceEvent、状态机和审计。
3. **思源纵向切片**：连接测试、选择笔记本、创建文档、追加块、幂等记录。
4. **人工闭环**：手动录入、候选列表、编辑审核、手动归档。
5. **异步流水线**：pg-boss、脱敏、模型抽取、去重、冲突和失败重试。
6. **规则引擎**：规则编辑、试运行、自动归档和审计。
7. **来源连接器**：Claude Code Hook、ChatGPT 显式保存、导出导入。
8. **交付强化**：搜索、备份恢复、指标、端到端测试和 NAS 安装文档。

## V1 验收标准

- 同一个事件重复提交十次只生成一组候选。
- 思源超时后任务进入重试，来源端在限定时间内正常返回。
- 敏感检测或冲突状态能够阻止自动归档。
- 自动规则能够先预览命中项，再由用户显式启用。
- 已归档内容能够显示对应思源块 ID、版本和完整审计链。
- NAS 重启后数据库、队列和归档状态保持一致。

## 开发启动状态

技术栈、V1 输入渠道、原始数据保留期、自动归档默认策略、思源目录结构和模型 Provider 方案均已确认，可以进入业务实现。
