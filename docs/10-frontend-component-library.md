# 前端组件库选型

状态：**已确认**  
日期：2026-08-14

## 结论

MemoryHub V1 采用 **Naive UI** 作为 Vue 3 管理端的基础组件库。

Naive UI 负责通用交互组件、组件状态和可访问性基础；MemoryHub 自定义主题 Token 与 CSS 负责产品布局、信息密度、排版和语义状态。业务代码不得散落硬编码主题色。

## 评估标准

- 与 Vue 3、TypeScript 和 Vite 的适配程度。
- 数据表格、表单、树、抽屉、对话框和反馈组件的完整度。
- 主题定制能力，以及构建深色模式和产品视觉语言的成本。
- 按需引入、产物体积和长期维护状态。
- 面向数据密集型管理界面的开发效率。

## 候选对比

| 方案            | 优势                                                                 | 不采用为 V1 基线的原因                                 |
| --------------- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| Naive UI        | Vue 3/TypeScript 原生、组件覆盖完整、主题 API 类型安全、按需引入友好 | 已选用                                                 |
| Element Plus    | 中文生态成熟，后台组件与资料丰富                                     | 默认视觉辨识度较强，产品化需要更多样式调整             |
| Ant Design Vue  | 企业级表格和表单能力成熟                                             | 体系较重，视觉和 API 约束强于本项目需要                |
| Arco Design Vue | 组件与主题能力完整                                                   | 社区规模和长期生态弱于首选候选                         |
| Vuetify         | 成熟、活跃、组件丰富                                                 | Material Design 约束不适合安静、密集、可扫描的工作界面 |
| shadcn-vue      | 可定制程度高，组件源码可直接维护                                     | 复杂表格和后台交互需要承担更多组装与维护成本           |
| PrimeVue        | 组件丰富                                                             | 原仓库已归档并迁移体系，不适合作为当前基线依赖         |

## 使用约定

### Provider 入口

全局主题和反馈上下文统一由 `apps/web/src/AppProviders.vue` 提供，包括：

- `NConfigProvider`
- `NDialogProvider`
- `NMessageProvider`
- `NNotificationProvider`

页面不得重复创建应用级 Provider。主题覆盖先集中在该入口；当 Token 数量增长后，再拆分到独立主题模块。

### Markdown 正文组件

记忆正文不直接使用裸 `NInput type="textarea"` 作为最终方案。手动录入与候选详情必须复用同一共享组件（建议名 `MemoryMarkdownEditor`）：

- 模式：仅预览（默认）、编辑、分屏
- 能力：风格切换、emoji 开关、模板套用、常用 emoji、字数统计
- 预览：Markdown 渲染 + HTML 清洗
- 约束：V1 不支持图片；不引入 LLM 润色或 WYSIWYG 富文本引擎

完整交互与排版规范见 [记忆正文 Markdown 与排版规范](13-memory-markdown-formatting.md)。

### 引入策略

组件在使用它的 Vue 文件中按需导入，不全局注册全部 Naive UI 组件。V1 优先使用：

- 布局与导航：`NLayout`、`NLayoutSider`、`NMenu`、`NTabs`
- 数据展示：`NDataTable`、`NDescriptions`、`NTag`、`NEmpty`
- 数据录入：`NForm`、`NInput`、`NSelect`、`NSwitch`
- 操作反馈：`NButton`、`NModal`、`NDrawer`、`NAlert`、`NSpin`

### 视觉边界

- 后台界面保持安静、紧凑、可扫描，不直接照搬演示站样式。
- 卡片仅用于独立对象或明确的工具容器，页面区块不层层套卡片。
- 颜色必须表达语义；品牌色、成功、警告、错误和信息状态保持区分。
- 优先使用 Naive UI 主题 Token，自定义 CSS 使用产品语义变量。
- 深色模式在实际业务壳层开发时一并设计，不在各页面独立实现。

## 风险与控制

| 风险                               | 控制方式                                               |
| ---------------------------------- | ------------------------------------------------------ |
| 页面直接硬编码颜色导致主题漂移     | ESLint/评审约束，集中管理主题 Token                    |
| 过度包装 Naive UI 导致维护成本上升 | 只封装重复业务模式，不为每个基础组件建立代理组件       |
| DataTable 大数据量性能不足         | V1 使用服务端分页；真实数据验证后再评估虚拟滚动        |
| 升级引入视觉或类型变化             | 锁定依赖版本范围，升级时执行组件测试和关键页面截图检查 |

## V1 验收条件

- 应用根节点已接入统一 Provider。
- 至少一个组件测试验证 Naive UI 正常渲染。
- 业务页面按需导入组件，不进行全量全局注册。
- 主题值不包含思源 Token、模型密钥或其他服务端配置。
