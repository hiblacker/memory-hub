# 产品与需求设计

## 产品定位

MemoryHub 是运行在个人 NAS 上的 AI 记忆收件箱。它负责收集 ChatGPT、Claude Code 和手动输入产生的候选记忆，让用户在可追溯界面中审核、修改、合并或拒绝，并按规则归档至思源笔记。

MemoryHub 不是新的聊天客户端，也不是思源替代品。数据库保存处理状态和审计历史，思源保存最终的人类可读知识。

## 目标

- 统一采集不同 AI 工具产生的长期记忆候选。
- 让每条记忆可查看来源、置信度、版本和归档结果。
- 支持人工审核和可解释的自动归档规则。
- 在思源不可用时可靠排队和重试，不丢失已批准记忆。
- 默认局域网自托管，允许使用本地模型完成脱敏和抽取。

## 非目标

- V1 不替换 ChatGPT、Claude Code 或思源的原生体验。
- V1 不向 ChatGPT 隐藏记忆数据库注入或读取其内部长期记忆。
- V1 不实现通用文档 RAG、移动应用、多租户 SaaS 或知识图谱浏览器。
- V1 不做思源到 MemoryHub 的完整双向同步。

## 关键用户流程

### 人工归档

1. 来源连接器提交一段对话或总结。
2. Worker 脱敏、分类并生成候选记忆。
3. 用户在收件箱查看候选与来源原文。
4. 用户编辑、合并、批准或拒绝。
5. 批准后写入选定的思源笔记本和路径。

### 自动归档

1. 候选记忆通过脱敏和去重。
2. 规则引擎检查类型、来源、项目、置信度、敏感等级和冲突状态。
3. 无冲突且满足规则的候选进入归档队列。
4. 思源适配器幂等写入并记录块 ID。
5. 失败进入指数退避，达到上限后进入死信列表等待人工处理。

## 记忆分类

| 类型       | 例子                           | 默认动作             |
| ---------- | ------------------------------ | -------------------- |
| 永久事实   | 稳定身份背景、长期使用的技术栈 | 高置信度时可自动归档 |
| 偏好       | 回答语言、代码风格、工作方式   | 高置信度时可自动归档 |
| 项目上下文 | 项目边界、环境、长期约束       | 默认审核             |
| 决策       | 技术选型及其原因               | 默认审核             |
| 临时状态   | 当前进度、短期上下文           | 保存但不自动归档     |
| 待办事项   | 下一步任务                     | 默认不作为长期记忆   |
| 敏感内容   | Token、密码、隐私数据          | 阻止归档并提示       |

## 成功指标

- 重复事件不会产生重复候选或思源块。
- 用户能从任意归档块追溯至来源会话和记忆版本。
- 思源短暂不可用不会阻断来源工具，恢复后能够自动补投。
- 自动归档规则可以先“试运行”，展示命中结果后再启用。
- 所有自动归档、修改和拒绝操作都有审计记录。
